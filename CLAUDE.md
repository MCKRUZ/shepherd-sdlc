# Shepherd — Development Instructions

## What This Is
Shepherd is a Claude Code plugin that orchestrates the full SDLC lifecycle using company-configurable profiles. It makes the AI-SDLC methodology executable within Claude Code.

## Architecture
- `plugin.json` — Plugin manifest (entry point for Claude Code)
- `SKILL.md` — Main skill definition (loaded when plugin activates)
- `commands/` — 32 slash commands (`/sprd`, `/sprd-setup`, `/sprd-status`, `/sprd-next`, `/sprd-gate`, `/sprd-enhance`, `/sprd-coach`, `/sprd-review`, `/sprd-intake`, `/sprd-brief`, `/sprd-spec`, `/sprd-spike`, `/sprd-sprint`, `/sprd-refine`, `/sprd-handoff`, `/sprd-spec-status`, `/sprd-audit`, `/sprd-audit-artifacts`, `/sprd-channel`, `/sprd-data`, `/sprd-doctor`, `/sprd-evals`, `/sprd-experience`, `/sprd-feature`, `/sprd-harness`, `/sprd-phase-report`, `/sprd-refresh`, `/sprd-retro`, `/sprd-revise`, `/sprd-rules`, `/sprd-upgrade`, `/sprd-version`)
- `agents/` — 14 agents (orchestrator, requirements-analyst, compliance-checker, section-evaluator, narrative-enhancer, gate-repair, multi-reviewer, discovery-analyst, document-summarizer, feature-architect, visual-designer, conversation-designer, data-analyst, bizreq-analyst)
- `channels/` — Cross-profile channel descriptor library (`_schema.yaml`, `ag-ui.yaml`, `voice.yaml`, `chat.yaml`) — the delivery-surface vocabulary the channel layer reads
- `profiles/` — Company/stack YAML configs with compliance gates
- `phases/` — Phase definitions (9 phases: 0, 1, 2, 3 Foundation, build loop, 7, 8, 9, close). The 4/5/6 gap is intentional — the batch Implementation/Quality/Testing phases are replaced by the continuous Build loop. Phase identity/ordering is owned by `scripts/phase_model.py` reading `phases/phase-registry.yaml`.
- `references/` — Progressive disclosure docs (loaded on-demand)
- `templates/` — Artifact templates copied to target projects
- `scripts/` — Python automation (uv runtime)
- `scripts/code_host.py` + `ado_import.py` (with `ado_map.py` / `ado_transport.py` / `ado_pipelines.py`), `ado_outcomes.py`, `import_outcomes.py`, `host_report.py` — the code-host provider layer: which host a repository is on (`github` / `azure-devops` / `none`), the `az` twin of the `gh` reads and writes returning the same dict shapes, the Azure DevOps scorecard import, and the top-level `host` block every host-touching `--json` carries. `references/code-host-providers.md` is the contract
- `hooks/` — PowerShell hooks for session/phase context injection
- `studio/` — the Shepherd desktop app, this plugin's **optional** Electron front end (Node/TypeScript, its own `package.json` and test suite). The plugin is fully usable without it, and nothing outside this folder depends on it. The Shepherd desktop app never reimplements plugin logic — it runs the scripts above the same way a person would. Its tests locate the plugin as their parent directory, so they always exercise the checkout they ship in. Every `claude` call the Shepherd desktop app makes uses flags declared in `studio/shared/claudeContract.ts` and probed once against `claude --help`, so an older Claude Code is reported ("lacks <flags> — update") rather than failing silently. Brand assets (mark, tiles, palette, brandbook) live in `docs/brand/shepherd/` — no wordmark file ships until its typeface is chosen (brand 4b); the team guides in `docs/guide/`. Upgrade round 2 (`docs/proposals/studio-upgrade-2.md`, 2026-10-06) added the Depth mark at hero size and the packaged app icon, readable dark-theme text tokens, one `PageHeader`/`Disclosure` kit for every screen, a measured fix for the ghost strip and the Board graph's fit, lit 3D bodies with a viewing reticle and ledger plates, a keyboard scope for the graphs, and sign-off / hand-off / project-open ceremonies that quieten with familiarity — no new dependency, nothing under `studio/electron/**`, the plugin's protected core (`scripts/`, `phases/`, `templates/`, `agents/`, `commands/`, `hooks/`, `profiles/`, `references/`) byte-for-byte untouched — pytest proves it. The command center (`docs/proposals/togo-command-center.md`, 2026-10-06) reorganised the app around the Build loop — a top band with an omnibar and an SVG lifecycle strip replace the sidebar; a sprint home (lanes · Today · In the room · Refining), planning, an in-place spec card, a close screen and a read-only steering mode draw one main-process `CommandCenter` read model with per-block provenance, and every write goes through a closed `sprint.py` argv table with the signed-in person as `--by` — alongside additive plugin verbs (`sprint.py list|log|carry|edit`, `spec_transition.py confirm-tier|assign`, `handoff.py --check`, `spec_readiness.py --all` + `ladder[]`, `record_findings.py report --json findings[]`) that leave every existing verb's text and exit codes byte-identical. See `studio/README.md`.

## Conventions
- Profile YAML validated against `profiles/_schema.yaml`
- Phase definitions use RFC 2119 keywords (MUST/SHOULD/MAY)
- Scripts use Python 3.12+ via uv
- State tracked in target project's `.sdlc/state.yaml`

## Design Rule: Standalone or Workflow
Every agent and command is a library part, not just a pipeline stage. Each one MUST be runnable
two ways: (1) composed into the phase workflow (reading `.sdlc/state.yaml` and the intake
catalog), and (2) standalone, pointed at arbitrary inputs with no `.sdlc/` present (degrade
gracefully: provisional IDs, explicit output paths, note the missing context in output headers).
When adding a new agent or command, document both modes in its file. `discovery-analyst` /
`/sprd-brief --docs <path>` is the reference implementation of this pattern.

## Key Features
- **Frozen layers** — Token-efficient phase summaries in `.sdlc/context/layers/` for cross-phase continuity
- **3-tier context** — Foundation (always loaded), frozen layers (per-phase), references (on-demand)
- **7-gate validation** — Integrity, completeness, metrics, compliance, consistency, quality, exit criteria
- **Narrative enhancement** — `/sprd-enhance` generates stakeholder-friendly `.narrative.md` companions
- **Conversational coaching** — `/sprd-coach` for adaptive guided dialogue through phases
- **Artifact checksums** — SHA-256 dirty tracking; gate checks skip unchanged artifacts
- **Smart repair** — `gate-repair` agent auto-fixes structural gate failures (missing templates, placeholders)
- **Dependency enforcement** — `check_dependencies.py` validates section DAG and implementation order
- **Multi-perspective review** — `/sprd-review` with adversarial, edge-case, and council modes
- **Brownfield detection** — Auto workspace scan in Phase 0 for existing codebases
- **Structured error specs** — Accepts/Returns/Errors required for P0/P1 requirements
- **Cross-artifact validation** — File reference checking between markdown artifacts
- **Question-to-file** — HITL open questions persisted to `open-questions.md` for audit trail
- **Test expansion** — Healer/Expander/bug-to-test patterns in the Build loop
- **Parallel review resolution** — Batch review findings by file in the Build loop
- **Session health check** — Opt-in pre-flight build verification at the start of Build-loop sessions (agent-executed, cross-platform)
- **Visual regression testing** — Optional screenshot capture during Build-loop E2E with baseline comparison (requires orchestrator integration)
- **Single-change guardrail** — Intentionally redundant constraints preventing concurrent spec work in the Build loop
- **Phase-scoped evaluation criteria** — `evaluation_criteria` with optional `phases` array for non-code artifact quality rubrics
- **Empirical metrics** — JSONL logging in `check_gates.py`, `validate_frozen_layer.py`, and `section-evaluator` agent to `.sdlc/metrics/`
- **Document intake** — Opt-in corpus analysis in Phase 0: scans external docs (RFPs, API specs, vendor docs), generates per-doc summaries with DOC-NNN IDs, creates token-budgeted intake index (Tier 1.5), enables Phase 1 requirement-to-source traceability
- **Spec authoring & Definition-of-Ready enforcement** — `/sprd-spec` is the Build-loop Intent beat: `new_spec.py` scaffolds `specs/NNNN-name.md` (auto-allocated id, risk tier a first-class frontmatter field) and `check_spec.py` enforces the DoR — required sections, valid risk tier, scope in *and* out, no placeholders — plus a vague-line lint that flags acceptance checks likely to fail the vague-line test (advisory). The agent proposes the risk tier; a human confirms it. Runs standalone or in-workflow (logs to `.sdlc/metrics/spec-log.jsonl`)
- **One-command hand-off (the Delegate beat's tool)** — `/sprd-handoff` / `handoff.py` turns branch + frontmatter + code-host assignment + starting the agent into one step. It refuses (repository untouched) unless the spec passes the DoR, the developer is in the roster and isn't also the spec's own checker, and the team is under its WIP limit (spec 0003's cadence-plan limits) unless `--over-limit "<reason>"` is given. Branch creation, the `status`/`developer` frontmatter commit, and the push all happen over plain `git` in a throwaway worktree — the caller's own checkout, dirty or not, is never touched — so the local half still works with no code-host access; only opening the draft PR and assigning/requesting review needs the repository's code-host CLI (`gh` on GitHub, `az` on Azure DevOps), and its failure is reported, not fatal. Idempotency is read from the spec's own branch on `origin`, not the caller's local checkout, since the frontmatter change never reaches a checkout still sitting on main. `--open` starts Claude Code on the branch in plan mode; without it, the exact command is printed
- **Spec status read from its pull request** — `/sprd-spec-status` / `spec_status.py` answers "where is this change, and who is it waiting on" straight from the code host: checks, whether the grader ran and its verdict, whether a required security review passed, approvals, and merge — never a status field someone forgot to update. `harness/profile/rubrics/grader.md` has the grader append a machine-readable `## Acceptance Check Verdicts` block to its PR comment (one row per acceptance check, `covered`/`not-covered`; the block wins over its own prose on disagreement) — the same `## <Heading>` + table convention as `/sprd-review`'s `## Gate Results`, now a third producer/consumer pair. `waiting_on` names the first unmet rung of the checking ladder in one line ("waiting for a non-author approval; requested from @priya-n 2 days ago"). No PR yet reports cleanly, not an error; no code-host access reports what was read locally and says the rest is unavailable — never "not started". The one write it makes, `status: merged`, lands once the PR merges as a commit straight onto the default branch, built from git plumbing (no checkout — the caller's own working copy is almost always already sitting on that same branch) and idempotent; a protected branch rejecting the push is reported, not fatal
- **Risk tier drives gate depth** — `risk_model.py` is the single source of truth for the risk taxonomy and the checking ladder (every tier blocks on CI + grader + correctness + non-author approval; HIGH adds a security pass and named sign-off; a gated path forces the security pass regardless of tier). `check_spec.py` enforces a spec's Checking Plan depth against its risk tier, so the tier sets the climb mechanically rather than as a label
- **Spec-backlog tracking (specs are the Build unit)** — the Build loop is spec-driven (one spec = one branch = one PR); `track_specs.py` derives backlog progress (status/risk breakdown, in-flight list, WIP-cap breaches) straight from spec frontmatter, so there is no separate tracker to drift. The section-plan/`sections-progress.json` model was retired from the Build loop; `check_dependencies.py` + `/deep-plan` sections are now Phase-2 *design* aids that feed the spec backlog
- **Steering scorecard (outcomes, not activity)** — `scorecard.py` records loop outcomes to `.sdlc/metrics/loop-events.jsonl` and reports the standard's numbers (accepted-as-is, review-wait median, rework/revert, bounce-back, escaped bugs, the DORA four; security-review wait on its own line). Reads "no data" rather than a fabricated zero, and *refuses* to record the forbidden activity metrics (velocity, story points, PR count, LOC). `steering-scorecard.md` is the client-facing artifact. `scorecard.py import --since <date>` builds the same events straight from GitHub's own history via the `gh` CLI (no stored credential — reuses the machine's existing sign-in): merged PRs, review-wait, deployments and closed `incident`-labelled issues, deduplicated on GitHub's own ids so re-running an overlapping window is a no-op. `github_import.py` is the pure mapping layer (`gh`-shaped dict in, event dict out), kept fully unit-testable with no live calls; hand-recording with `record` still works unchanged
- **Code-host providers — GitHub (`gh`) or Azure DevOps (`az`), chosen by the repository** — the code lives on both hosts, so every PR-facing read and write (spec status, hand-off, connection report, branch policies, pipeline evidence, gate credentials, scorecard import) works on either, and no doc or screen may claim `gh` is required to open a project or read a PR. **Two axes, never merged:** the *code host* (PRs, identity, policies) comes from the `origin` remote; the *CI platform* (pipeline dirs, runs, secrets) comes from the harness manifest, as `doctor.py` already reads it — GitHub + Azure Pipelines is legitimate and a mismatch is reported, never resolved silently. **Override precedence:** `--host` flag > `SHEPHERD_CODE_HOST` env (or `SDLC_CODE_HOST`, the pre-2.0 name, still read) > `.sdlc/code-host.yaml` (written by `set_setting.py code-host`, travels with the clone) > the parsed remote > the manifest as a tie-breaker when there is no usable remote > `none`, which falls through to `gh` exactly as before. **Identity:** the roster key stays `@handle`; `people[].email` (optional, unique) is the only way an Azure DevOps sign-in (UPN) resolves to a handle — never a guess from a display name. **Honesty:** `cli_state` reads `unknown` when a probe could not run, a value Azure DevOps does not record is `null` (`updatedAt`, vote time, request time) or the key is omitted (`wait_hours`), an unreadable category reads "not imported", never a zero; "unavailable" rides the top-level `host` block (`{name, source, cli, cli_state, detail}`) and is never a false `no`. **The Shepherd desktop app's typed-actor rule:** when the host cannot say who is signed in (PAT-only `az`), a typed name is allowed only in that state and every ledger line records `accountSource: typed`. **Protected core untouched:** `scorecard.py`, `github_import.py`, `doctor.py`, `check_gates.py`, `check_spec.py`, `advance_phase.py`, `phase_model.py`, `new_spec.py`, `harness/**` are byte-identical; existing GitHub argv is pinned by `test_gh_argv_golden.py` and no existing test was edited. **Fixtures carry provenance:** `scripts/tests/fixtures/code_host/azure_devops/captured/*.json` is real `az` output captured 2026-10-05 and anonymised (`CAPTURE-NOTES.md` lists every fact it settled); the hand-written documents above it stay marked `hand-written (unverified)` and `test_fixture_provenance.py` lists what is still unverified. See `references/code-host-providers.md` and `docs/proposals/code-host-providers.md`
- **Finding memory & disposition tracking (Context Repair, Increment A)** — `/sprd-review` now writes a machine-readable `## Gate Results` block (id/category/severity/target/disposition/detail) that `record_findings.py` parses into an append-only ledger `.sdlc/metrics/findings-log.jsonl`, so a finding survives the report being overwritten and its disposition is tracked across rounds. `findings_model.py` is the single source of truth for the severity↔gate mapping and the disposition state machine (FIXED/SPLIT/ACCEPTED_RISK/POSTPONED/OPEN) with honest counting — a mislabeled disposition (SPLIT without id+owner, an AI signing ACCEPTED_RISK) still counts as debt. The review stays **advisory** (the grader advises, never blocks); only the **FIXED-claim check** may block (`report --strict` exits 2) — a finding marked FIXED whose target file never changed is a factual false claim, not a judgment. The ledger is what later makes a recurring finding promotable into a permanent check (Phase C: "findings become new checks"). Runs standalone (`--repo`) or in-workflow (`--state`). See `docs/proposals/context-repair-loop.md`
- **Multi-discipline channel layer** — an additive layer giving Data, Design, and Bizreq first-class seats and organizing a feature around its **customer channel of use**. `channels/` holds schema-guarded YAML descriptors (`ag-ui`, `voice`, `chat`) whose acceptance dimensions ride a spec's *existing* `## Acceptance Checks`; `validate_channel.py` guards the library and `check_channel.py` is an advisory (exit 0) DoR lint that never changes a ready/not-ready verdict. Six commands (`/sprd-feature`, `/sprd-experience`, `/sprd-data`, `/sprd-rules`, `/sprd-channel`, `/sprd-evals`, `/sprd-harness`, `/sprd-upgrade`) drive five interview-driven discipline agents (`feature-architect`, `visual-designer`, `conversation-designer`, `data-analyst`, `bizreq-analyst`) that also serve as `/sprd-review` council lenses (7 viewpoints). A spec's optional `channel:` frontmatter field binds the surface; a phase-spanning `.sdlc/decision-log.md` (owner + 2-business-day clock, surfaced in `/sprd-status` via `track_decisions.py`) and optional discipline sign-offs on the state sign-off record round it out. The protected core (`check_spec.py`, `check_gates.py`, `section-evaluator`, `harness/**`, `phase_model.py`, `phase-registry.yaml`, `/sprd-coach`, `/sprd-spec`) is byte-for-byte unchanged. See `references/channel-model.md` and `references/team-model.md`
- **Close handoff-report generation** — Phase C Step 4 ("Hand over the record") is a two-pass draft: `generate_handoff_report.py` does the deterministic assembly first — phase report index, per-phase gate/sign-off table (from `state.yaml`), metrics history (reusing `scorecard.py`), spec backlog (reusing `track_specs.py`) — filling the existing `final-handoff-report.md` template and marking the judgment sections (outcomes vs the Phase 0 statement, debt log, open items, dashboard handover) with `[Fill: ...]` slots for the Explore agent to enrich. Honest by design (missing data reads "no data", never a fabricated zero) and refuses to clobber a human-edited report without `--force`. Runs standalone (`--repo`) or in-workflow (`--state`)
- **Artifact update & audit** — an additive, advisory layer for *changing* a pre-Build artifact after the fact and auditing the trail. `artifact_model.py` owns the change-ledger entry shape and the staleness disposition state machine (`OPEN → REFRESHED | ACKNOWLEDGED | NOT_AFFECTED`) with honest counting (ACKNOWLEDGED needs an owner, NOT_AFFECTED a reason, or it still counts as debt); `artifact_lineage.py` harvests declared `upstream → downstream` edges (frozen-layer `source_artifacts`, id references, explicit markdown paths) with a labeled **coarse** phase-order fallback and cycle-safe traversal. `audit_artifacts.py` (`record` / `impact` / `report`, **exit 0 always**) records changes to an append-only `.sdlc/metrics/artifact-log.jsonl` — its **own** JSONL, never inside `gate_results`, so `/sprd-audit` output is byte-identical with or without it — and flags a downstream as a *stale candidate* when an upstream changed after it last did. `/sprd-revise <id|file#section>` is the PM-facing write path (discipline agent proposes, named human decides; records the why to the ledger **and** a linked `DL-NN` decision-log item; re-gates; shows impact to disposition). `/sprd-audit-artifacts` is the read-only sibling to `/sprd-audit` (freshness dashboard, `--impact`, `--history`). A `record --scan` step in `/sprd-next` captures direct edits at advance time; `/sprd-status` surfaces a stale rollup. The protected core (incl. `advance_phase.py`) is byte-for-byte unchanged. See `references/artifact-lifecycle.md`
- **Artifact versioning & draft+confirm auto-refresh** — an additive, advisory package built on the artifact-update-audit layer that (1) gives every pre-Build artifact a **content history** (diff/rollback) and (2) back-propagates a merged spec's shipped reality **up** into `requirements.md`/`epics.md`/`feature-brief.md`/`business-rules.md`. One new **pure** module `version_model.py` derives the ordinal-keyed version list `v1..vN` straight from the change-ledger's existing 16-hex SHA-256 hashes — the content-addressed object store (`.sdlc/versions/objects/<xx>/<16hex>`) is just those hashes rehydrated to bytes, so there is **no second index** to drift (a dup-hash rollback is its own ordinal, rendered "restored from vX"; a pre-existing file with no ledger entry synthesizes a `v1` baseline, never a crash). The `version` + `refresh` verbs **fold into `audit_artifacts.py`** (the sanctioned extend target; its existing `record`/`impact`/`report` output stays byte-identical) so one best-effort `capture()` seam keeps content↔hash lockstep. `/sprd-version {list,show,diff,rollback,gc}` is the read/undo path (rollback is preview→named-human-confirm, append-only, `--ack-signoff` for signed-off artifacts, refuses on an uncaptured version; `gc` is cross-ledger refcounted and protects unknown sign-offs). `/sprd-refresh {detect,scan,draft,apply,reject,status}` is the reverse-propagation path: **review-first / divergence-aware** (a faithful spec drafts nothing without `--draft`), the discipline agent edits only a `.proposed`, a named human echoes the reviewed diffhash to `apply` (One Rule), and the refresh lands as a rollback-able `refreshed` version attributed to the spec via a `source_spec` **rider key** (`artifact_model.py` unchanged). Both write **nothing** to `state.yaml` (re-gating stays the command layer's `/sprd-gate` job) and exit 0 on every path; the object store and `.proposed` drafts are **gitignored** local safety nets (a fresh clone/CI degrades to "content not captured", documented override to commit). The protected core is byte-for-byte unchanged. See `references/artifact-versioning.md`
- **Cross-ledger retro roll-up** — `retro_report.py` (surfaced as `/sprd-retro`) is the read-only report that turns the accumulated ledgers into retro input: recurring findings grouped by category+target across review rounds (candidates for a permanent check — the "findings become new checks" feed), repeat-stale artifacts, the **refresh funnel** per merged spec and per upstream stem (detected → drifted → refreshed → rejected → open — the tuning signal for the divergence heuristic), and a combined disposition-debt rollup naming each source ledger. Same discipline as the scorecard: "no data" over fabricated zeros, patterns keyed by category/artifact/stem and **never by actor** (no ranking flag exists), refuses activity metrics, writes nothing, exit 0 on every path, dual-mode `--repo`/`--state`
- **Command contract lint** — `scripts/tests/test_command_contracts.py` is the static half of the command-prose safety harness: it extracts every `uv run … scripts/<name>.py` invocation from fenced blocks in `commands/*.md` and validates script existence, subcommand chains, and every `--flag` against live `--help` output (cached subprocesses), plus agent-name and `references/`/`templates/` path cross-references. Conservative by design (ambiguous → skipped, never a false violation; intentional exceptions live in an explained allowlist) with self-tests proving each detection class fires. Live "does-the-model-follow-the-doc" evals remain out of scope
- **Template shapes — documents read and written without losing anything** — a machine-readable `<name>.shape.yaml` beside a template (`templates/_shape-schema.yaml` is the format; `scripts/validate_shape.py` enforces it, every error naming its line) declares that template's sections and fields (label, a fixed `type`, `required`, guidance). `scripts/document_shape.py` reads and writes real documents against a shape as exact byte spans into the original text — never a parse-and-regenerate model — so a document round-trips byte-for-byte when nothing changed and a real edit touches only the bytes it targets; nothing recognized is ever silently dropped (every byte lands in some block, proven by a tiling test). A document reads as free text only when NO section is recognized; one that lacks a *required* section still reads as sections, with the gap in `warnings` (read contract 3), and a section whose fields are all optional may be absent silently, and a `## ` section a person added that the shape doesn't declare reads as an editable `custom` section of its own (one whole-body field) rather than raw text. `scripts/tests/test_shapes_cover_templates.py` fails when a template gains a section its shape doesn't declare. A repeating block (`requirements.md`'s `### FR-001`, `### FR-002`, ...) gets its next number by scanning the *whole* document, including free text, so a number is never reused. `scripts/check_document_completeness.py` is a new, separate, always-exit-0 advisory check that reports a required field absent or empty — including a required *section* deleted outright, which the existing string-only Gate 2 scan can't see. `check_gates.py` and the rest of the protected core are byte-for-byte untouched; whether this new check ever gates anything is a later, deliberate decision. Shapes ship for the 28 templates that already carry a `<!-- REQUIRED: -->` marker, plus `foundation-report` and `build-handoff` — the two Foundation documents authored through Shepherd's chat, where a missing shape meant a proposed write could never land ("no usable shape"); the rest are unaffected. Shepherd starts a not-yet-created document from its template on the first accepted proposal (`ensureDocumentFromTemplate`). See `docs/templates-artifacts.md` §1
- **`document_shape_cli.py` — a subprocess surface over the shape library (Shepherd spec 0009 prerequisite)** — `document_shape.py` is a pure library with no CLI; Shepherd (the desktop app) is a separate TypeScript process that can only call it as a program. The wrapper adds no judgment of its own, only serialization: `read --doc --shape` emits the library's block model as JSON, and `write --doc --updates` applies `[start, end, new_text]` span replacements — both converting between the library's Python-string (code-point) offsets and the UTF-8 byte offsets a Node caller actually needs to slice a decoded string correctly (these templates are full of em dashes and curly quotes, so the two diverge in practice, not just in theory). A byte offset that doesn't land on an exact character boundary is refused with a clear error rather than silently misresolving. `write` takes no `--shape` — span replacement doesn't consult it. Both commands open files with `newline=""`, preserving the library's byte-identical round-trip guarantee. Exit 0/1 (not the rest of this system's advisory always-0), since this is a mechanical serialization layer, not a judgment call. **`add-row` (spec 0020)** appends ONE row to a markdown table, as a single exact span through `write_document()` so every other byte (line endings included) is untouched: addressed by shape (`--shape --section --field`, a `table`-typed field, its first table) or by position with no shape at all (`--table-index N`, code fences skipped). The second form exists because `business-rules.md`, `golden-scenarios.md` and `decision-log.md` are a preamble plus one table with **no `## ` heading** — a shape can only anchor to a `## ` heading, and real projects' copies have none either — so they cannot be shaped and are appended to by position instead. `--cells` (or `--cells-file`, to avoid shell quoting) maps column header → value; `--id-column`/`--id-pattern "BR-%02d"` allocates the next free id by scanning the **whole** document (prose included, so an id is never reused) and a width is a minimum (`BR-%02d` reads `BR-100` whole — `pattern_to_regex` once read it as `BR-10` and issued `BR-100` twice). **It removes nothing by default**: `--replace-placeholders` clears template stand-in rows (more than half the non-empty cells hold a `[bracketed]` or `<angle>` span; links and HTML tags are content) and only from a table made *entirely* of them — a table with any real row loses nothing, because deleting a person's row on a heuristic is the failure this verb must not have (the first version did, caught by the correctness review of its PR); ids in rows that were not removed still count as used. Every refusal exits 1 with the document unchanged. Spec 0020 also adds shapes for 14 discipline templates (workshop brief, contradiction/question lists, document registry/summary, feature brief, user stories, the data and experience documents, spike) and a shared `templates/review-report.md` (its `## Gate Results` table starts empty, so `add-row` builds a report finding by finding and `record_findings.py` ingests it); `test_shapes_cover_templates.py` and `test_shaped_templates_roundtrip.py` cover them automatically.
- **`stage_readiness.py` — "what does this stage still need", in one read-only call (spec 0010)** — composes the stage's required artifacts and its plain-language exit conditions (via `phase_model`), completeness findings (via `check_document_completeness`'s pure `check_document`), and sign-off state read straight from `state.yaml`.
