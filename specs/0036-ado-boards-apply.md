## Goal
A named person can put what `plan` showed onto the Azure DevOps board as themselves, and nothing else can: `ado_sync.py apply --confirm <12hex> --by <human>` creates and updates the mirrored work items in tree order (outcome, domain, requirement, epic, feature, spec), field writes first and comments after, each update guarded by a `test /rev`; `link-pr` links a spec's pull request to its work item; `iteration bind` binds a sprint to an iteration path; `posture` switches a clone between `plan-only` and `assisted`; and `comment` drafts a comment row (from a person's message, or from the repository's own ledgers for the eleven `comments.events`) that only an `apply` sends. Every write is ledgered to `.sdlc/metrics/ado-sync-log.jsonl`, none is sent with an AI or agent as `--by`, and none is sent while the signed-in `az` identity differs from `--by`.

## Why
Fold B2 showed what the mirror would write; the value of the mirror (nobody keeps the board up to date by hand) arrives only when it writes. This is the first time Shepherd writes to a system outside the repository, and it writes as a person: a comment it drafted and a human confirmed is, on the board, indistinguishable from one the human typed — same author, same notification to every follower. A write against a stale revision would overwrite a colleague's change; a POST retried after a timeout would post twice; a plan confirmed while `az` is signed in as someone else would put words in that person's name. So every guard is mechanical rather than a label: the plan hash a human types, `ai_by` on every `--by`, the executing identity read before any other call and compared with `--by` for the whole plan, `test /rev` on every update, a closed idempotency key per comment, recovery by `text_sha` on an unknown outcome instead of a second POST, and an argv golden that proves no notification suppression, rule bypass, delete or comment edit is ever sent.

## Risk Tier
**Tier:** HIGH
**Why this tier:** this Fold writes to a system outside the repository, as a person. A work item it creates or updates notifies that item's followers exactly as a colleague's edit would, a comment it posts carries the signed-in person's name with no visible difference from one they typed, and none of it can be taken back by reverting a commit — a posted comment or a revision stays in the board's history. The failure modes are an overwrite of a colleague's change (guarded by `test /rev`), a double post (guarded by the idempotency key and the recovery re-list), and words confirmed into someone else's name (guarded by the identity check before any spawn). The Pod Lead may not lower it.

## Decision List
- **Only a person sends, and only as themselves.** An AI or agent `--by` is refused (exit 2) on every write verb; a plan holding a comment row is refused whole (exit 2, nothing sent) unless the signed-in identity, read first, is the roster person named by `--by`; a service principal reads as `identity_unknown`. Owner: @MCKRUZ. Answer: refuse, never warn.
- **An unknown outcome is recovered, never retried.** A comment POST that timed out or failed without a readable answer is followed by one re-list (`order=desc`, `$top=20`); a comment with the row's `text_sha`, by the same identity, created within 10 minutes is ledgered `commented{recovered: true}` and nothing is posted again. Owner: @MCKRUZ. Answer: re-list, match, ledger.
- **A comment is keyed, so it is posted once.** Every comment row carries a closed idempotency key per event (free text is hashed, never written into the key); a key already on a `commented` ledger line is never drafted again. Owner: @MCKRUZ. Answer: one key rule per event.
