## Goal
The whole Phase-1 and Build record becomes navigable on the client's Azure Boards, and text people change there flows back as a proposal a named person lands. Five opt-in kinds join the mirror — the lifecycle singleton (the phase, gate and sign-off record from `state.yaml`), NFRs, business rules (`BR-NN`), discovery questions (`Q-NN`) and measurements — each planned and applied through the existing `plan`, confirm, `apply --confirm <hash> --by <human>` handshake. `pull` can read only what changed through the `reporting/workItemRevisions` watermark feed instead of re-reading every item. `reconcile --take ado` on a board edit to a co-owned text field writes `<artifact>.proposed` (design D32) by splicing the board's text into the document's exact byte span, never the artifact itself. Shepherd, the desktop app, gains a reconcile dialog and a `Pull now` button, both driven by the existing closed argv table. Mentions become real board mentions only once the B0 capture says which identity notifies.

## Why
Folds B1 to B4 mirror the Build record (specs, features, epics, requirements, domains, outcomes, spikes, sprints, decisions, findings), but a team that runs its refinement on the board still cannot see the NFRs a spec must meet, the business rules a feature carries, the questions still open from discovery, or where the project stands in its lifecycle without opening the repository. Every one of those has an owner and a shape already, so each can ride the same plan-hash handshake and the same ownership table without a second write path. Reading the board item by item does not scale past a few hundred items, and the reporting feed is the API's own answer to "what changed since I last looked". And a board edit to an epic's or an FR's text is today reported but cannot be taken: the `.proposed` writer closes that half of the co-ownership loop without ever letting board text overwrite an artifact.

## Risk Tier
**Tier:** MEDIUM
**Why this tier:** every board write in this Fold goes through Fold B3's existing `apply` handshake (a 12-hex plan hash a person typed, a human `--by`, `posture: assisted`), so no new write path to the external system exists, and every new kind is opt-in. The feed only reads. It is not LOW because it brings text typed on the board by people outside the team back into the repository's working copy as `.proposed` files, puts five new kinds of record in front of a client, and reaches the harness permission pack (through `sync_kit.py` only). A wrong owner letter for a breadth kind would make a board edit read as drift the repository overwrites; the B5-P0 pins hold every letter to the design's §6.1 table. Undoing it is deleting new files, the appended rows and one dialog; no existing behaviour changes. The desktop delta stays in the renderer; nothing under `studio/electron/**` changes. Owner: @MCKRUZ. Answer: append, never reorder.
